# ZCnova BGM Studio

動画用の BGM を、その場で計算して作る道具です。**HTML ファイル 1 枚**で動きます。

曲調と長さを選ぶだけで 1 曲できます。音はすべて Web Audio API とアプリ内の
生成アルゴリズムでその場で作っていて、既存の楽曲・BGM 素材・サンプル音源は
1 つも使っていません。作った曲は MP3 / WAV で書き出せます。

| | |
|---|---|
| 本体 | `ZCNOVA_BGM_v5.6.html`（約 820KB・1 枚で完結） |
| 版 | 5.6 |
| 動くところ | Chrome / Edge / Firefox / Safari の新しめの版 |
| 必要なもの | インターネット接続（音の部品を CDN から読むため） |

- フレーズを並べて長さを作る

- **MP3 / WAV** で書き出す

## 権利について

生成した BGM は、動画・配信・SNS などに基本的に自由に使えます。
既存の楽曲・BGM 素材・録音素材を 1 つも使っていないためです。

詳しくはアプリ画面いちばん下の「ライセンス・利用について」、または
[`public/ライセンスと利用について.txt`](public/ライセンスと利用について.txt)。

## フォルダの中身

```
ZCNOVA_BGM_v5.6.html    本体。これ 1 枚で動く
public/                 URLで公開するときの中身（★ git に入れる）
  index.html              本体と同じもの。URL を短くするため index に
  robots.txt / _headers   検索・配信の設定
  公開のしかた.txt          置き方の手順書
dist/                   配布物。組み立て直せるので中身は git に入れない
  zcnova-bgm-studio-v5.6.zip   手元で使う版一式
  blogger/                     ブログに貼り付ける版
build/make-dist.mjs     配布物と public/ を組み立てる
tests/                  検査一式（142件）
docs/心地よい音の実測メモ.md   音づくりの実測記録
sri-hash-tool.html      CDN の SRI ハッシュを取り直す道具
```

**`dist/` と `public/` は扱いが違います。**

| | git に入れる？ | なぜ |
|---|---|---|
| `dist/` の中身 | 入れない | 毎回組み立て直せる |
| **`public/`** | **入れる** | 公開するファイルそのもの。ホスティングは git にあるファイルしか見ないので、外すとサイトが空になる |

## 開発

```bash
npm install                    # playwright と terser
npx playwright install chromium

npm test                       # 検査一式（142件・およそ3.5分）
node tests/run.mjs 08          # 番号の合うものだけ

npm run build                  # dist/ と public/ を組み立て直す
```

Playwright を全体に入れてある環境では次を指定できます。

```bash
export ZC_PLAYWRIGHT=/path/to/playwright/index.js
export ZC_TERSER=/path/to/terser/main.js
```

### 配るときの決めごと

| | どう書き出すか | なぜ |
|---|---|---|
| 日本語の `.txt` | **BOM 付き・CRLF** | BOM が無いと Windows のメモ帳が Shift-JIS と誤解して化ける。LF だけだと改行されず 1 行に見える |
| `.html` | BOM なし | `<meta charset>` で自分で名乗れる。BOM があると先頭に見えない文字が入る |
| `robots.txt` | BOM なし | BOM があると巡回側が 1 行目を読み損なう |

`build/make-dist.mjs` が全部そろえて書き出し、検査⑳が見張っています。

### 検査が守っているもの

音は聴かないと分かりませんが、**聴かないと分からないものは、聴かないと
壊れたことにも気づけません**。数字にして固定してあります。

| | 中身 |
|---|---|
| ① 生成の健全性 | 全曲調 × 全拍子 × 小節数（465曲）に例外・無音・壊れた音名が無い／選んだ長さに届く |
| ② 指紋 | 決まった 62 曲をパートごとに突き合わせ、意図しない変化を見つける |
| ③ SRI | CDN のハッシュがずれていない（ずれるとアプリが起動しない） |
| ⑦ スラー | 管・弦が舌／弓で切りすぎない（音源まで届いているかも実測） |
| ⑧ 音域・音量 | 全楽器を G4 でそろえて 0.2dB 以内／高い音が刺さらない |
| ⑨ 編成 | その編成にあるべき楽器が鳴る／伴奏の形が楽器に合っている |
| ⑫⑱ 重さ | 1 音あたりの部品数・毎秒の部品数・同時発音数の上限 |
| ⑰ 書き出し | 音が割れない／動画に乗る音量 |
| ⑲ 独奏 | 「◯◯だけ」の伴奏が鍵盤の書き方になっていない |
| ⑳ 公開用・説明書 | `public/` を実際にサーバーへ置いて曲ができて鳴る／日本語の説明書が Windows で読める |
| ㉑ 音源スペック | 32楽器のパラメーター（音域・ユニゾン・歪み・包絡線・ビブラート）が控えと一致する |
| ㉒ ④の表示 | 各パートに楽器名が出る／聞こえないパートは沈んで理由が出る／ミュート・ソロ・③の入切に追従する |

くわしくは [`tests/README.md`](tests/README.md)。

## 音づくりの記録

「耳に触る」「電子音っぽい」「割れて止まる」を 1 つずつ潰したときの
**測り方と数字**を [`docs/心地よい音の実測メモ.md`](docs/心地よい音の実測メモ.md)
にまとめてあります。本体の先頭にも同じ内容の索引が入っています。

要点だけ:

- 音量は必ず**同じ高さ**で測る（A 特性は周波数で変わるので、楽器ごとの中央音で
  測ると比べたことにならない）
- **音色を差し替えただけでは、その楽器の音にならない**。その楽器が実際にやる
  動きまで写して初めてその楽器に聞こえる
- 「音が割れて止まる」は音量ではなく**計算量**の問題
- **正規化のある系で「音量を下げる」は、何もしないのと同じ**。下げるべきは
  音の強さではなく、音の性質と比率
- ボタンの絵を**文字で描いてはいけない**（字体に無いと番号が描かれる）
- 日本語の `.txt` は **BOM 付き・CRLF** で配る（無いと Windows のメモ帳が
  Shift-JIS と誤解して化ける。HTML と `robots.txt` には付けない）
