# 人間が心地よく聞ける音 ― 実測メモ

ZCNOVA BGM Studio を作りながら「耳に触る」「電子音っぽい」「割れて止まる」を
1つずつ潰していったときの、**測り方と数字**をまとめたもの。
次に音楽まわりを作るときは、ここの数字を出発点にすれば同じ回り道をしなくて済む。

数字はすべてこのアプリで実際に測った値。感覚ではない。

---

## 0. まず「測り方」を決める

ここを間違えると、直すたびに別のところが壊れる。実際に何度も踏んだ。

### 0-1. 音量は必ず**同じ高さの音**で測る
A特性（人の耳の感じ方の重み付け）は周波数で大きく変わる。
楽器ごとに「その楽器の音域の真ん中」で測ると、高い楽器ほど大きく出るので
**比べたことにならない**。

一度これを破って、楽器ごとの中央音で測って音量をそろえた結果:

| | 直す前 | 中央音で「そろえた」後 |
|---|---|---|
| ホルン | 63.4dB | 63.4dB |
| トランペット | 63.3dB | 57.8dB |
| フルート | 54.0dB | 54.0dB（ホルンの9dB下） |

金管・リードの一群は元から 0.8dB 以内にそろっていたのに、
そろえたつもりで 5.6dB に広げてしまい、「吹奏楽なのに笛が聞こえない・
ただのシンセに聞こえる」状態になった。

**決めごと: 全部 G4（392Hz）で測る。音域外の楽器はその上限で測る。**

### 0-2. A特性だけでは足りない
A特性は「純音1本」の感じ方の近似。倍音が広く散らばったノコギリ波のような音は
**実際よりずっと小さく見積もられる**。

そこで **臨界帯域（Bark）ごとの和**も併用する。

```
帯域ごとの音量を出す → それぞれを 0.23 乗する → 全部足す
```

A特性では小さく出ていたのに、この測り方では上位だったもの:

| 音色 | 臨界帯域の「うるささ」 |
|---|---|
| アコーディオン | 22.0（全音色中1位） |
| シンセ | 21.5（管楽器の一群と同じ） |
| リード | 20.5 |
| 厚みパッド | 20.5 |

「リード・シンセ・アコーディオンの初期音量が大きすぎる」という耳の指摘は
A特性では説明できず、この測り方で初めて数字になった。**耳のほうが正しかった。**

### 0-3. その他の測り方

| 測るもの | 方法 | 判定 |
|---|---|---|
| ざわつき（うなり） | 音量の包絡のうち **15〜70Hz** 成分の割合 | 3%以下 |
| 生きた揺れ | 音量の包絡のうち **0.15〜8Hz** 成分の割合 | 3%以上 |
| 立ち上がりのはね | 頭のピーク ÷ 伸ばしているときの音量 | 4倍以内 |
| 余韻 | 音符が終わってから −40dB に落ちるまで | 1.3秒以内 |
| 再生の詰まり | 予約時刻 − **生の時計**（`context.currentTime`） | 0.03秒を切ったら遅れ |

## 1. 音量をそろえる

G4 で測って **58.5dB の1本の線**にそろえる。実測の幅 **0.2dB**（そろえる前は 11.9dB）。

そのための倍率（`ZC_INST_TRIM`）:

| 楽器 | 素の音量(G4) | 倍率 |
|---|---|---|
| ホルン / トロンボーン | 63.4dB | 0.57 |
| トランペット | 63.3dB | 0.58 |
| サックス | 62.8dB | 0.61 |
| オーボエ / ブラス | 62.6dB | 0.62 |
| ファゴット | 61.7dB | 0.69 |
| クラリネット | 58.4dB | 1.00（基準） |
| チューバ | 57.5dB | 1.12 |
| チェロ | 55.9dB | 1.35 |
| フルート | 54.0dB | 1.68 |
| ピッコロ | 51.5dB | 2.24 |

臨界帯域で測り直して下げたもの: アコーディオン 0.55 / シンセ 0.55 /
リード 2.65（3.40から）/ 厚みパッド 0.78。

**要点**: 「一群としてすでにそろっているもの」は崩さず、**一群まるごと**動かす。
1つだけ下げると、そこだけ穴が空く。

## 2. 高さ（音域）

### 2-1. 「出せる音域」と「BGMに使ってよい音域」は別
物理的に出せても、動画の下で鳴ると刺さる高さがある。実際に鳴らして決めた上限:

| 楽器 | BGMの上限 | 備考 |
|---|---|---|
| サックス | 76（E5） | いちばん低い上限。強く吹くと刺さる |
| トランペット | 79（G5） | |
| クラリネット | 86 | |
| シンセ / リード / レトロ / 厚み / パッド | 84（C6） | |
| 鉄琴 | 72〜84（C5〜C6） | 元は G5〜C7。まるごと1オクターブ下げた |
| ピッコロ | 67〜84（G4〜C6） | 元は D5〜C7 |
| エレピ / バイオリン / フルート / 弦 / ピアノ | 88 | |

### 2-2. 天井
**C7（MIDI 96）より上の音は作らない。** 1音でも混じると耳に刺さる。

### 2-3. 居座らせない
「上限以内」でも、**上の方に居続ける**と疲れる。
C6 より上に居る割合の上限を **26%** に。

| | 直す前 | 直した後 |
|---|---|---|
| 鉄琴 | 58% | 24% |
| ピッコロ | 47% | ― |
| ハープ | 37% | ― |
| 刻み・装飾（sub）| 56%（G5超）| 26% |

### 2-4. 高い音は音量も下げる
C5（72）以下はそのまま。それより上は `1 - (音の高さ-72)*0.045`（下限0.32）。
C6 で 0.46（−6.7dB）、C7 以上で 0.32（−10dB）。

## 3. 跳躍（オクターブ跳び）

「変に高くはねて耳に触る」の正体。**平均は滑らかなのに、時々とんでもなく跳ぶ**。

| 見るところ | 直す前 | 上限 | 直した後 |
|---|---|---|---|
| 旋律の跳躍（フレーズの中） | 最大34半音 | 14半音 | 14半音 |
| 低音の跳躍 | 最大22半音 | 12半音 | 12半音 |
| **フレーズのつなぎ目** | 21.9%が12半音以上・最大37半音 | 12半音未満 | **0%・最大11半音** |
| 和音の重心 | 平均3.1半音・7半音以上20.4% | ― | 平均1.5半音・0.5% |

### 3-1. つなぎ目がいちばん見落とされる
フレーズの中だけならしても、**フレーズとフレーズの境目**は誰も見ていなかった。
曲はフレーズを並べて作るので、跳びの大半はここに残る。

**つなぎ目ごとに直してはいけない。** 同じフレーズが曲の中で何度も使われるので、
「前が何だったか」で直すと同じフレーズが場所によって違う高さになり、
書き出し（フレーズ1種類につき1回だけ計算する）と再生がずれる。

**正しいやり方**: どのフレーズも**同じ高さで始まり、同じ高さで終わる**ようにする。

1. パート全体の中央の高さ（目標）を出す
2. フレーズの1音目を、目標にいちばん近いオクターブへ置く
3. そこから順に、跳躍が上限を超えたらオクターブで折り返す
4. 最後の音も目標へ寄せる。1音では届かないときは**後ろ向きに**折り返し直す
   （1音目は動かさない約束なので、1音目との跳躍が上限に収まるときだけ採用）

### 3-2. 音域合わせは「パートまるごと」で1回だけ
フレーズごとに best を選ぶと、**それ自体がつなぎ目を跳ばせる**。

### 3-3. 直したことの確かめ方
音の**位置・数・並び順・テンポ・楽器・和音・ドラムが1つも変わらず**、
動いた音の差が**すべて12の倍数**であることを、直す前の出力と突き合わせて確認する。
（実測: 80曲22442音のうち3765音が動き、全部12の倍数だった）

## 4. 伸ばす音

計算で作った音は、長く伸ばすほど作り物っぽさが出る。動画のBGMでは特に邪魔になる。

| | 直す前 | 直した後 |
|---|---|---|
| 金管ハーモニー(wind2) の音の長さ | 平均1.05秒・**51%が1秒超** | 平均0.52秒・4%が1秒超 |
| パッドの余韻（音符の後に残る長さ）| 1.57〜1.80秒 | 1.20〜1.26秒 |

原因は「いちばん短い選択肢が4分音符しかなく、短い音を鳴らせない作りだった」こと。
選択肢ごと1段ずつ短い側へずらす。

**サステイン（伸ばしているときの音量）** は逆に上げる。低すぎると音が痩せて
「はねて細くなる」形になる: シンセ 0.20→0.55 / レトロ 0.12→0.45 /
エレピ 0.12→0.35 / やわらか 0.20→0.45。

## 5. 生きた揺れ

**完全に止まっている音は、それだけで電子音に聞こえる。**
人が吹いても弾いても、音量も高さもわずかに動き続ける。

止まっていた4つの音色に、ゆっくりのうねり＋ビブラートを入れた:

| 音色 | うねり | 深さ | ビブラート | 深さ | 実測の揺れ |
|---|---|---|---|---|---|
| シンセ | 0.31Hz | 0.12 | 5.1Hz | 0.042 | 8.4%（前 0%）|
| レトロ | 0.37Hz | 0.11 | 4.7Hz | 0.040 | 9.7% |
| エレピ | 0.27Hz | 0.10 | 5.4Hz | 0.034 | 5.7% |
| やわらか | 0.23Hz | 0.10 | 4.9Hz | 0.034 | 4.6% |

- 深さ 0.12 ＝ 音量で約1.0dB のうねり。**±0.6dB では「静止している」印象が変わらなかった。**
- 揺れは**曲の頭に同期**させること（`sync()`）。していないと再生と書き出しで音が変わる。
- 管楽器・弦楽器は「奏者1人につき揺れ1本」を共有する。音ごとに揺れを作ると
  1個あたり約5ms かかり、書き出しが遅い最大の原因になっていた。

## 6. ざわつき（うなり）

高い音が耳につくとき、**まず疑うのは音量ではなく「うなり」**。

デチューン（`spread`）で重ねた音は、高い音ほど倍音どうしが速くうなる。

```
リード spread 16 … C4 では毎秒 2.4回（気持ちのいいコーラス）
                   C6 では 3〜6倍音が毎秒 30〜60回
```

人の耳がいちばん「ざらつく」と感じるのが **毎秒15〜70回**。ちょうどここに入る。

| | spread | C6でのざわつき |
|---|---|---|
| リード | 16 → 10 | 6.8% → 1.4% |
| 厚みパッド | 30 → 18 | 30.7% → 1.2% |

低い音の厚みは変わらない（リード 0% / 厚みパッド 0.2%）。
**高いところだけで問題になるので、高いところだけ直す。**

## 7. 書き出しの音量

動画に乗せて使える大きさ:

- **ピークは 0.95 以下**（実測 0.83〜0.89）
- **実効値（RMS）は 0.05〜0.30**（実測 0.15〜0.24）

出口の作り: `音量 → 低域カット38Hz → 明るさ12kHz → 3.2kHzを-2.5dB →
圧縮(-18dB/3:1) → 持ち上げ1.35 → 0.7 → リミッター(-1dB) → tanh の頭打ち`

- **リミッターだけでは足りない。** Tone.Limiter は実体がコンプレッサーなので
  瞬間のピークを通す（実測で 1.07 まで出ていた）。最後に `tanh` で頭打ちにする。
- **3.2kHz を1つだけ凹ませる**のが効く。耳がいちばん敏感な帯域で、
  低域の薄い曲ではここがむき出しになる。全体を暗くせずに刺さりだけ取れる。

## 8. 重さ ― いちばん見落としやすい

**「音が割れて止まる」は、音量の問題ではなく計算量の問題だった。**

### 8-1. Tone.js の部品は1個ではない

この端末で1個作って本物の Web Audio の部品を数えた実測:

| 書いたもの | 本物の部品 | 内訳 |
|---|---|---|
| `Tone.Filter` | **15個** | Gain10・ConstantSource4・Biquad1 |
| `Tone.Oscillator` | **8個** | Gain5・ConstantSource2・波1 |
| `Tone.Noise` | **7個** | Gain5・音源1・波形1 |
| `Tone.Gain` | 1個 | |
| `Tone.WaveShaper` | 1個 | |

`ConstantSource` は「鳴りっぱなしの音源」なので、**置いてあるだけで計算を食う**。

### 8-2. 実測

管楽器の1音ぶんは **62個**にもなっていた。再生12秒での実測:

| 編成 | 直す前（毎秒つくる部品） | 直した後 |
|---|---|---|
| 吹奏楽 | 852個（同時に鳴る音 最大31） | 303個 |
| オーケストラ | 585個 | 237個 |
| フルバンド | 653個 | 399個 |
| 金管 | 502個 | 212個 |
| ピアノ | 113個 | 113個 |

**管楽器の編成だけが 5〜7倍重い。** 「サックス・トランペットが絡むと割れる」が
これで説明できる。

### 8-3. なぜ気づけなかったか
音の計算が間に合わない詰まりは**音の計算の側（オーディオスレッド）**で起きる。
こちらが見ていた「予約の余裕」は**画面の側**の数字なので、**そこには映らない**。
自動で軽くする仕組みも働かないままだった。

→ **重さは「間に合っているか」ではなく「部品を毎秒いくつ作っているか」で見る。**

### 8-4. 直し方
音ごとに作る部品は Tone の包みではなく**生の Web Audio** にする。
発振器・フィルタ・ノイズだけ差し替えれば足りる（Gain と WaveShaper は元から1個）。

- 倍音表から作る波（PeriodicWave）は**楽器ごとに作り置き**する。1枚 2.5ms かかる。
- 息／弓のノイズのもとは**2秒ぶん1本**だけ持って、鳴らし始める場所をずらして使い回す。
  （2チャンネルにすること。1チャンネルにすると息の音が真ん中に張り付く）

**結果: 1音 62個 → 19個（簡易版 26個 → 7個）。書き出しも同じだけ速くなる。**

### 8-5. 音が変わっていないことの確かめ方
16の楽器を同じ条件（G4・1.2秒・強さ0.85）で書き出し、直す前と突き合わせる:

- 実効値の差 0.00〜0.02dB
- 音量の形の差 0.06dB 以内（100msごと・14点）
- 帯域の分布差 0.1ポイント以内（6帯域）
- ピークだけは差が出る（鉄琴0.67dB）→ 息／撥のノイズが毎回ちがう乱数なので、
  **実効値が合っていれば同じ**と判断してよい

### 8-6. 同時発音数の上限
「楽器1つぶん」の上限だけでは足りない。7パート同時の編成では、
どの楽器も「自分は余裕」と判断したまま全体が膨らむ。
**楽器をまたいだ数**でも上限を持つこと（実測の最大は28なので、40 を安全弁に）。

## 9. やってはいけないこと（全部やらかした）

1. **楽器ごとに違う高さで音量を測る** → そろえたつもりで 0.8dB → 5.6dB に広げた
2. **A特性だけで判断する** → 広帯域の音（アコーディオン・シンセ）を見落とす
3. **簡易版へ落とす判定を「楽器1台の重なり」で見る**
   → 楽器1つの編成では旋律も和音も同じ1台に集まるので、
     全体は軽いのにその1台だけがしきい値に届く。実測で **51%が簡易版**になり
     「管楽器なのにただのシンセ」に聞こえていた
4. **伸ばす音を簡易版へ落とす** → 長い音の途中で音色が本来↔簡易を行き来して
   「乱れ」に聞こえる。短い音は簡易版でもほとんど区別がつかないので、
   **落とすなら短い音から**
5. **書き出しでも簡易版へ落とす** → 書き出しは実時間で動かないので間に合わなくなる
   ことが無い。落とす理由がそもそも無い（実測 51% → 0%）
6. **`Tone.now()` で遅れを測る** → 先読み 0.3秒 が足されるので、正常でも
   83% が「遅れ」判定になる。生の時計（`context.currentTime`）で測ること
7. **予想の所要時間を画面に書く** → 曲の長さ・音の数・端末で大きく変わるので必ず外れる。
   外れた数字は「壊れているのでは」という不安のもとになる。
   書いてよいのは**いま動いている証拠としての経過時間**だけ

## 10. 直したら必ず測り直す

このメモの数字はすべて自動検査で見張っている（97件）。
音は聴かないと分からないが、**聴かないと分からないものは、聴かないと壊れたことにも
気づけない**。数字にして固定しておけば、次に触ったときに落ちてくれる。

音楽そのものが変わる直しをしたときは、**「変わったのはオクターブだけ」を
突き合わせで証明してから**、控え（指紋）を取り直すこと。
